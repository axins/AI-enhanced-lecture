# AI-enhanced-lecture

如何用 AI agent 高效备课：扩充课程材料、重做 ppt、核查事实、建设参考资料库，并设计 AI 增强的课堂与作业。

本仓库提供一个可直接使用的 CodeBuddy / Claude Skill：**`ai-enhanced-lecture-prep`**（当前版本 **3.1**）。

它沉淀了一套把一门大学社科课程从「几十页课件」扩展为「可讲授、可核查、可复用」的完整讲义的工作流，重点解决的是 **AI 在备课中到底该怎么用** 这个问题。

---

## 核心主张

> 在备课中，AI 的第一价值不是「帮你写」，而是「帮你发现错误」。

讲稿一旦进入课堂，错误的代价远高于论文——它会被几十名学生同时接收，且难以撤回。因此本 skill 把 AI 定位为**审计者**，其次才是检索者、结构化助手与对抗性陪练。

四个杠杆（详见 `ai-enhanced-lecture-prep/references/ai-for-prep.md`）：

| 杠杆 | AI 的角色 | 典型动作 |
|---|---|---|
| 一 | **审计者** | 时效审计、一致性审计、重复审计、盲点审计 |
| 二 | 检索者 | 补全文献出处、定位官方一手来源、找中英文媒体、比对冲突数值 |
| 三 | 结构化助手 | 把密集页面转成表格/板书/连续谱；为讨论题搭脚手架 |
| 四 | 对抗性陪练 | 扮演挑剔学生挑刺；生成反事实提问；预判误解点 |

配套方法：**三回答对照法**——学生先独立作答，再由 AI 作答，逐项对照差异，最后对 AI 输出做反向核查。目的不是让 AI 给标准答案，而是让学生看见自己的思考过程，并学会审计机器的回答。

## v3 新增

> v3.1 撤回了 v3 中试行的「案例前置」阶段，工作流回到八阶段 P0—P7；其余变更保持不变。

| 变更 | 内容 |
|---|---|
| **来源分级** | 每条依据标 T1—T4（文书/官方原文 → 权威署名报道 → 整理稿/百科 → 不可考）；新增 `references/source-tiers.md` |
| **冲突并列** | 同一事实出现两个数值时并列两说并各标等级，不自行取舍；新增失败模式「数值冲突只留一说」 |
| **引语纪律** | 只有整理稿、没有逐字实录时写「据……转述」，不得加引号当原话 |
| **待核清单** | 每份交付物末尾固定附「待核清单」，写明未取到的原始文本与结论 |
| **格式兜底** | `.ppt`/`.doc` 明确报错并提示另存，不再返回 0 页让后续步骤跑在空基线上 |
| **新脚本** | `source_audit.py`：检查链接是否漏标类型/等级、等级与域名是否矛盾、是否缺待核清单 |
| **性能** | 解析缓存、链接并发、单遍扫描、二分定位（见下表实测） |

### 实测性能（同一台机器，同一批材料）

| 场景 | 2.x | v3 |
|---|---|---|
| 347 页课件解析 | 每次调用各解析一遍（1.34s） | 首次 1.34s，之后 **0.01s**（缓存命中） |
| 109 条链接存活性校验 | 逐条串行 **231.0s** | 8 线程 **38.3s**；再跑一次 **0.0s**（结果缓存） |
| 质检 / 进度报告 | 每文件两轮读盘 + 全文反复正则 | 单遍扫描，线性耗时 |
| 待核条目页号定位 | 每个标记回溯全文 | 一次预扫描 + 二分查找 |

## 工作流

| 阶段 | 名称 | 交付物 |
|---|---|---|
| P0 | 盘点与基线 | `page_index.md`（页序 + 页数指纹） |
| P1 | 骨架生成 | 讲稿骨架（每页四块） |
| P2 | 逐页扩展 | 按六类维度填充 + 三子块 |
| P3 | 质检 | 覆盖度/重复/顺序/维度/来源等级校验报告 |
| P4 | 事实核查 | 核查清单（清零）+ 来源等级 + 冲突并列 |
| P5 | 资料总库 | 五分类参考资料库 |
| P6 | 交叉一致性 | 一致性报告（查冲突、查重复、统一术语） |
| P7 | 教学交付 | 讨论题、实证题目库、AI 活动、评分标准 |

关键纪律：**核查优先于扩展**（错误基础上的扩展会大量返工）、**逐页推进不批量**（一次性生成整册必然塌方）、**无法确认即标记**（标记是资产，不是瑕疵）、**来源分级冲突并列**（不自行取舍）。

## 快速开始

```bash
# 1. 盘点课件（首次解析后进缓存）
python scripts/deck_index.py 课件.pptx --out page_index.md --json page_index.json

# 2. 生成讲稿骨架
python scripts/scaffold_lecture.py 课件.pptx --out 讲稿.md

# 3. （逐页扩展后）质检
python scripts/qa_lecture.py 讲稿.md --deck 课件.pptx --partial --strict

# 4. 抽取待核实条目并逐条核查
python scripts/extract_todo.py --dir . --out verify_list.md

# 5. 来源分级审计
python scripts/source_audit.py --dir . --strict

# 6. 校验参考链接（并发 + 缓存）
python scripts/check_links.py --dir . --jobs 8

# 7. 进度报告
python scripts/progress_report.py --dir . --json progress.json
```

依赖：`python-pptx`（P0/P1/P3）。未安装时脚本给出 `pip install` 提示并返回退出码 2。

退出码统一：`0` 通过 / `1` 存在待处理问题 / `2` 环境或参数错误。

## 讲稿体例

每页四块：

```markdown
## 第 N 页　<页面标题>

【页面内容】……（课件原文与备注）

【讲稿要点】……（一句话判断：本页最该讲的一处）

【需补充】
- ◤理论◢  ◤人物◢  ◤案例◢  ◤文献◢  ◤实践◢  ◤互动◢
```

核心条目另加三子块：`【历史脉络】`、`【逻辑关联】`（写明回接哪一讲哪一页）、`【参考链接】`（`[类型][等级] <URL>（访问日期）`）。文件尾固定附「待核清单」。
