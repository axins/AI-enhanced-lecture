# 备课与核查提示词库

本文件提供可直接复用的提示词。`<占位>` 需替换。所有提示词与学科无关。

**使用通则**：

- 优先使用"要清单"类提示词，而非"直接改写"类——先让 AI 指出问题，再由人工决定如何改
- 凡涉及具体卷期、条号、年份、数据的输出，追加一句"**无法确认的条目请明确标注，不要猜测**"
- 要求 AI 输出"位置 + 问题 + 建议改法"三元组，避免泛泛批评

---

## P0 盘点

```
读取课件 <文件路径>，导出：
①总页数；
②每页的页号、版式名称、首行文本；
③无文字的页（图片页）单独列出。
输出为 Markdown 表格。不要省略任何一页。
```

## P1 骨架

```
按以下体例为课件第 <起始页>—<结束页> 页生成讲稿骨架：

## 第 N 页　<页面标题>
【页面内容】
【讲稿要点】
【需补充】
- ◤理论◢
- ◤人物◢
- ◤案例◢
- ◤文献◢
- ◤实践◢
- ◤互动◢

【页面内容】填该页原文（含备注）。无文字的页标题写"（空白页）"。
不要填充【需补充】，留空待后续扩展。
```

## P2 逐页扩展

```
为下面这一页补充教学内容。要求：

1. 【讲稿要点】写一句话判断——本页最该讲的一处是什么，不要复述页面内容。
2. 【需补充】按六类维度各给至少一条：
   ◤理论◢ 概念澄清与理论来源
   ◤人物◢ 学者代表作与学派归属
   ◤案例◢ 案例事实补全与可类比案例
   ◤文献◢ 完整出处（作者、篇名、期刊/出版社、卷期、页码、年份）
   ◤实践◢ 制度现状、时效更新、数据
   ◤互动◢ 课堂提问，并附参考答案或引路要点
3. 凡无法确认的人名拼写、卷期、条号、数据，一律写「需核实」，不要猜测。
4. 指出本页面内容与本课程其他讲次的关联，写明"回接 第 N 讲 第 x 页"。

页面内容：
<粘贴页面全文与备注>
```

### 三子块扩展

```
对 <核心理论/人物/研究/数据/案例> 补三个子块：

【历史脉络】产生背景、演进阶段、当代发展。
【逻辑关联】与本课程哪些讲次、哪些理论相关，写明具体页号。
【参考链接】按五类给出：
  - [数据库DOI]
  - [开放获取]
  - [官方一手]
  - [媒体报道]
  - [判例数据]
每条链接标注访问日期。检索不到的类型写「未检索到权威来源」，
不要编造 URL，不要用相近链接充数。
```

## P4 事实核查

### 逐条核查

```
核查以下条目：<条目>

请实际检索后回答：
①权威依据是什么（给出来源名称与链接）；
②正确表述应当是什么；
③若检索不到，明确说"未检索到权威来源"。

无法确认的请直接说明，不要给出看似确定但不确定的答案。
```

### 批量时效审计

```
下面是本课程 <范围> 的全部文本。请列出**可能已过时**的条目，包括：
- 已废止或被修订的规范名称、条号、施行日期
- 已更名或撤并的机构
- 明显属于多年前的统计数据（指出年份）
- 已变化的社会事实

对每一条输出：位置｜原文表述｜为什么怀疑｜建议如何核实。
不要直接改写文本，只要清单。
```

## P6 一致性审计

### 人名与术语

```
下面是本课程的多个文件。请检查：
①同一人名在不同文件中拼写是否一致，列出全部不一致项；
②同一概念是否使用了多个译名或表述，列出并建议统一为哪一个；
③同一数据在不同文件中数值或年份是否冲突。

输出冲突清单：条目｜A 处表述（位置）｜B 处表述（位置）｜建议。
```

### 作业要求一致性（必做）

```
下面是本课程的课件文本与教学大纲。请逐项比对并列出冲突：
- 作业字数
- 提交材料项数与名称
- 评分条目数量与内容
- 汇报时长
- 案例范围或其他限制条件

输出表格：项目｜课件第 X 页｜课件第 Y 页｜大纲｜是否一致。
特别注意：评分标准的分值合计是否等于总分。
```

### 重复内容审计

```
下面是本课程第 <N> 讲与第 <M> 讲的内容。请：
①找出两讲之间高度相似的段落；
②判断每处重复是"必要呼应"还是"无意义重复"；
③对无意义重复，给出分工建议：哪一讲讲什么角度、明确排除什么内容。

输出表格：重复内容｜第 N 讲位置｜第 M 讲位置｜判断｜分工建议。
```

## 盲点审计

```
下面是已完成的一讲讲稿。请以最挑剔的读者身份指出问题，每一条输出：
位置｜问题｜建议改法。

重点检查：
①论证跳跃——从前提推不出结论的地方；
②反例缺失——存在但未被提及的反例或相反研究；
③群体盲区——分析是否忽略了某一相关群体的处境；
④证据薄弱——缺乏可核验支撑的论断；
⑤学生视角——最可能被质疑、最容易误解的地方。

不要泛泛批评，每条必须给出具体位置。
```

## 结构化助手

```
把下面这段内容转化为 <表格 / 连续谱 / 板书结构 / 检查清单>。

要求：
①可直接粘贴进讲稿的 Markdown；
②每一格有实质内容，不要同义重复或留空；
③控制在本页可讲完的体量（建议 3—6 行/项）。

内容：
<粘贴>
```

### 讨论题脚手架

```
为下面这道讨论题准备教学支架：
①参考答案（2—3 条，不是唯一答案）；
②引路要点——帮助学生不跑偏的抓手；
③可能的跑偏方向及如何拉回；
④若学生回答冷淡，可用的追问。

题目：<题目>
```

## 对抗性陪练

```
在 <讲稿内容> 中，请扮演以下角色之一，输出你的质疑：

【挑剔的学生】指出这段论证中最站不住脚的一处，并说明理由。
【外行提问者】用完全不懂本学科的人能理解的方式追问，直到暴露含糊之处。
【对立立场者】为本讲结论的反面写出最强论证。
【期末考生】如果考这道题，标准答案的采分点是什么？
【反事实提问者】如果 <关键条件> 改变，结论会怎样变化？
```

## P7 教学交付

### 实证题目设计

```
为本课程第 <N> 讲设计 <数量> 个可供学生完成的实证研究题目。

每个题目须包含：
①研究问题；
②检验的是本讲哪一页的哪个命题；
③方法与样本量（定性 ≥50 例 / 定量 ≥100 例）；
④数据来源与可核验性说明；
⑤可能的困难与应对。

优先选择：与本讲核心理论直接对应、数据可得、工作量可控的题目。
```

### 课堂组织设计

```
为本讲的案例讨论设计课堂组织方案：
①分组方式与人数；
②各环节时间分配；
③汇报与交叉质询规则；
④教师收束时应回到的理论要点；
⑤若时间不足，可压缩的环节。
```
