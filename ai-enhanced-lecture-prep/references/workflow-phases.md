# 八阶段详细流程与交付物

本文件按阶段说明动作、交付物与验收标准。各阶段严格顺序推进；P4（核查）必须在 P2（扩展）之后、但在该讲交付之前完成。

---

## P0　盘点与基线

**目标**：在开始写作前，建立可核对的页序基线，防止后续缺页、错页、误改原文件。

**动作**：

1. 用 `deck_index.py` 导出课件的页序索引（页号、版式、首行文本）
2. 记录原文件页数指纹（页数与每页首行），写入基线文件
3. 抽查若干页的全文与备注，确认文本抽取完整（尤其是图片页、表格页）
4. 清点配套材料：大纲、阅读材料、既有讲义、往年版课件

**交付物**：`page_index.md`（页序 + 页数指纹 + 配套材料清单）

**验收**：页数与课件实际页数一致；图片页被明确标出（无文字页不能静默跳过）。

**要点**：原课件文件在本流程中**不应被修改**；如需改动，先备份并在基线中记录。

---

## P1　骨架生成

**目标**：按页序生成讲稿骨架，使后续扩展有固定落点。

**动作**：

1. 用 `scaffold_lecture.py` 生成骨架
2. 文件头写入体例说明（标注维度含义、子块格式、标记词约定）
3. 文件尾预留两个附录：本讲最需要修改的若干处、可供学生做的实证研究题目
4. 用课件原文填充【页面内容】（含备注）

**交付物**：`<课程>-第N讲-讲稿与教案.md`（骨架版）

**验收**：页数与 P0 基线一致；每页四个块齐全。

**要点**：页面标题取该页首行；若首行为空（图片页），标题写"（空白页）"并在【需补充】中给出处理建议（保留/删减/替换为某图）。

---

## P2　逐页扩展

**目标**：按六类维度填充内容；对核心条目追加三子块。

**动作**：

1. 每页先写【讲稿要点】——一句话指出本页最该讲的一处，这是全页的锚
2. 按维度补充，每类至少一条，重点页可多条
3. 对核心条目追加【历史脉络】【逻辑关联】【参考链接】
4. 交叉引用写明"回接 第 N 讲 第 x 页"
5. 无法确认的一律写标记词（默认 `需核实`）

**交付物**：讲稿填充版

**验收**：每页至少 3 条补充；全讲至少 3 条跨讲引用；链接均带类型标签与访问日期。

**推进纪律**：

- **分批推进，不要一次性输出整册**。建议每批 10—15 页，或按章节分段
- 每批完成后立即用 `qa_lecture.py` 校验
- 连续空白页超过 2 页时，在讲稿中给出删减建议

**写作要点**：

- 【讲稿要点】要给出**判断**，不要复述页面内容
- ◤互动◢ 必须附参考答案或引路要点，否则讨论会散
- ◤实践◢ 涉及现行制度/数据时，注明时效并给出更新建议
- 涉及价值分歧的议题，用**分析框架**处理（成本收益、功能/反功能、多方立场），不作宣判

---

## P3　质检

**目标**：用脚本做机械校验，用清单做人工校验。

**动作**：

1. 运行 `qa_lecture.py`：页序覆盖、重复、顺序、维度计数、标记词计数；分批推进时加 `--partial`，交付前加 `--strict`
2. 运行 `source_audit.py`：链接是否标类型与等级、等级与域名是否矛盾、是否缺待核清单
3. 人工检查：每页【讲稿要点】是否为判断句；◤互动◢ 是否都有参考答案
4. 检查空白页处理

**交付物**：校验报告（脚本输出）

**验收**：见 `qa-rubric.md` 的门槛清单。

---

## P4　事实核查

**目标**：清零标记词，消除已知错误。

**动作**：

1. 用 `extract_todo.py` 生成核查清单（含页号定位与结论列）
2. 逐条检索核实，**每条标 T1—T4 等级**（口径见 `source-tiers.md`）
3. **回写**：查到权威依据后直接改写正文并**删除标记词**；同时补上 `[类型][等级]` 与访问日期
4. **数值冲突**：两说并列写出并各标等级，注明「未取到文书原文」，不得自行择一
5. **只有整理稿**：写「据……转述」，不得加引号当作原话
6. **查不到的**：改写为「未检索到权威来源，建议课堂上不引用」，不得保留含糊表述
7. 在文件尾补齐「待核清单」，写明每条未取到的原始文本
8. 核查完成后重跑 `extract_todo.py` 与 `source_audit.py`，确认归零

**交付物**：核查清单（清零版）+ 更新后的讲稿

**验收**：标记词归零或每条均有明确结论；所有链接有类型与等级；无凭记忆写出的卷期、条号、人名；无「只有一说」的冲突数值；待核清单章节存在。

**优先级**：先查"会在课堂上被学生指出"的条目（条号、人名拼写、数据年份），再查文献卷期，最后查出处存疑的引用。

**要点**：核查必须**先于**进一步扩展。在错误基础上做扩展，返工成本极高。

---

## P5　资料总库

**目标**：把分散在各讲的链接集中存放，便于检索与复用。

**动作**：

1. 用 `reference-repo-template.md` 建库
2. 按五类组织：**人物 / 理论 / 研究 / 数据 / 案例**
3. **随讲次同步累积**，不要最后一次性生成（否则必然遗漏）
4. 每条含：名称、简介、类型标签、链接、访问日期
5. 定期用 `check_links.py` 校验存活性，失效的更新或标注

**交付物**：`<课程>参考资料总库.md`

**验收**：五类均有条目；每条有类型标签与访问日期；存活性校验通过。

---

## P6　交叉一致性

**目标**：消除课程内部的冲突与无意义重复。

**动作**：

1. **一致性审计**：人名拼写、术语、数据、作业要求（字数/材料项数/评分条目/时长）在课件各页与大纲之间是否一致
2. **重复审计**：识别跨讲次重复内容，给出分工方案
3. **术语统一**：同一概念的多译名，选定一种并全局替换
4. 把发现的问题写入各讲的"本讲最需要修改的若干处"附录

**交付物**：一致性报告 + 讲稿修正

**验收**：无互相冲突的作业要求；所有跨讲重复内容均有明确分工。

**要点**：作业要求不一致是最容易被学生发现、也最损害课程可信度的问题。交付前必须做一次全课程扫描。

---

## P7　教学交付

**目标**：产出课堂上可直接使用的材料。

**动作**：

1. **讨论题**：为每讲准备讨论题 + 参考答案 + 引路要点 + 可能的跑偏方向
2. **实证题目库**：按课程作业要求（如定性 ≥50 例 / 定量 ≥100 例）设计可做的题目，每题标明检验哪一页的哪个命题
3. **AI 增强活动**：按 `ai-pedagogy.md` 选择并嵌入
4. **课堂组织建议**：分组方式、时间分配、汇报与质询规则
5. **评分标准**：与大纲一致，且分数合计正确

**交付物**：课堂可用材料（附在讲稿尾部或独立文件）

**验收**：讨论题均有参考答案；实证题目均标明对应的理论命题；评分标准与大纲一致且分数合计无误。

## 附录：一讲的标准文件结构

```
<课程>-第N讲-讲稿与教案.md
├── 文件头：体例说明（维度含义、子块格式、标记词约定、来源等级口径）
├── 第 1 页 …… 第 N 页（按页序）
├── 附：本讲最需要修改的若干处（按优先级）
├── 附：本讲可供学生做的实证研究题目
└── 附：待核清单（固定，不可省）
```

## 附录：跨讲推进顺序

两种可选顺序，按用户偏好选择：

| 顺序 | 特点 |
|---|---|
| **按讲序推进** | 每讲完成即可交付使用；适合边上课边准备 |
| **按优先级分批** | 优先处理时效性最强、问题最多的讲次；适合集中备课 |

无论哪种，每讲都必须完整走完 P0—P7，不做跨讲并行。
